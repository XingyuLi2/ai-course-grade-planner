# 项目学习笔记：流程、结构化数据与验证

更新：2026-11-25。结合课程成绩规划 Demo 的评分规则提取、目标试算与分数持续更新，记录产品任务、结构化数据、状态管理和评测之间的关系。

## 1. 从页面优化回到用户任务

### 概念

用户任务描述的是想完成什么，例如“新成绩公布后，知道距离目标还差多少”。页面布局是完成任务的方式。缩短表单可以减少滚动，但仍需检查是否保留了不必要的输入步骤。

### 本项目应用

初版要求逐项填写课程。页面过长、术语难懂的反馈出现后，先将表单拆成三步；随后围绕省去材料整理的核心需求，改为材料生成成绩表，规则编辑移到生成之后。

修正入口仍然保留，因为生成结果可能需要纠正。它用于核对已有结果，不再要求每位用户从空表重抄课程。

### 例子与问题

如果材料已经写明“作业 A 占 30%，满分 20”，生成后的用户任务应是核对这两项，而不是重新找到空输入框并抄写。

思考：如果只把一张长表分成三页，用户少做了哪些事情？如果没有减少步骤，哪些任务负担仍然存在？

相关内容：[产品需求](../docs/product-requirements.md)、[导入界面](../dist/import-view.mjs)、[规则修正界面](../dist/rules-view.mjs)。

## 2. 结构化输出与事实依据

### 概念

结构化输出把内容拆成可显示、保存和校验的字段。格式正确与内容正确是两层检查：JSON 可以被解析，不代表字段的含义和数值都来自材料。

### 本项目应用

[提取 Prompt](../prompts/extract-rules.md) 分别要求权重、满分、实际／预计、额外及格要求和来源。缺失值保持为空，冲突保留各方信息，不支持的规则保留原文。

当前已准备 Prompt 和 5 个合成案例，真实模型实验尚未运行。网页采用配套材料的模拟提取，计算模块独立处理核对后的规则。

### 例子与问题

“期末占 50%”表示它占课程总评的比例，不能推出期末满分为 100，也不能推出最低分为 50%。这三个信息应该放进不同字段，并分别有依据。

思考：如何区分“材料没有写满分”和“满分是零”？两份材料分别写最低分 40% 和 50% 时，为什么不能按出现顺序直接覆盖？

相关内容：[案例与人工答案](../evaluation/cases.jsonl)、[实验方法](../evaluation/README.md)。

## 3. 用状态区分事实、假设和未知

### 概念

状态决定数据现在代表什么，以及能够参与哪一种计算。相同数字放在不同状态中，会形成不同含义：实际零分是已公布结果，预计零分是试算假设，空白则是未知。

### 本项目应用

实际成绩进入已取得的总评分；预计只用于试算。实际存在时使用实际，录入实际确认后清空本项旧预计，保留其他项目。

### 例子与问题

作业 B 满分 40、占 20%，预计 30 时贡献 15 分；实际公布 32 后贡献 16 分。两者不能相加。实际贡献变化后，剩余要求也要从同一份记录重新计算。

思考：“按预计可以达标”与“当前已经达标”有什么区别？如果总评已经够分，但期末实际成绩低于单项最低分，应如何展示？

相关内容：[状态设计](../docs/state-design.md)、[成绩编辑模块](../dist/score-edit.mjs)、[计算测试](../tests/calculation.test.mjs)。

## 4. 草稿、提交与保存

### 概念

编辑中的值、用户已经确认的值、已经持久保存的值，可能处于不同阶段。设计确认和取消时，需要明确每一步是否改变正式记录，以及失败后保留什么。

### 本项目应用

已出成绩先编辑草稿，再核对原值与新值，最后确认提交。取消恢复原记录；保存失败时保留页面内修改并显示未保存，多标签变化暂停覆盖。

开发检查曾发现：重试保存可能提前写入尚未确认的规则草稿。修复后，重试使用原已接受记录；正式保存规则时才接受草稿。

### 例子与问题

B 已出成绩为 32，在弹窗输入 31 后点击取消，记录应仍为 32。点击确认后，如果浏览器拒绝写入，则应说明页面已更新但尚未保存。

思考：为什么修改实际成绩需要核对，而预计分数可以直接调整？为什么“重试保存”不应顺便确认其他草稿？

相关内容：[开发检查记录](../docs/verification-import-demo-2026-11-25.md)、[存储模块](../dist/storage.mjs)。

## 5. 分层验证与独立答案

### 概念

计算正确、模型提取正确、用户会用，是不同的问题，需要不同证据。测试时的预期答案应独立于待测实现，避免重复同一种错误。

### 本项目应用

| 验证层 | 主要回答的问题 |
| --- | --- |
| 计算与自动检查 | 已覆盖输入下的换算、倒推和数据更新是否符合预期 |
| 真实浏览器操作 | 弹窗、文件选择、保存恢复、键盘和排版是否正常 |
| 模型提取实验 | 材料中的字段、来源、冲突及特殊规则是否被准确保留 |
| 用户任务观察 | 用户能否完成任务、理解结果，在哪里发生误解或求助 |

现有 93 项自动检查包括计算 52、存储 13、成绩编辑 11、应用事件 14、启动 3。部分使用 DOM 和内存存储替身，因此完整浏览器验收仍单独记录。模型实验与同学观察尚未执行。

### 例子与问题

如果计算程序把权重 20% 误当成 20，使用同一程序生成的答案也可能包含相同错误。人工基准应从公式独立算出预期，再与程序结果比较。

思考：为什么模拟提取成功不能计入模型准确率？为什么一张正确页面截图不能单独证明刷新后数据仍然保留？

相关内容：[测试说明](../tests/README.md)、[验证说明](../docs/validation.md)、[浏览器清单](../docs/browser-checklist.md)。

## 6. 复盘问题与演示自检

使用合成课程演示一遍：生成成绩表 → 核对规则 → 预计 B 为 30 → 解释期末要求 72 → 实际 B 为 32 → 解释期末要求 70 → 修改后取消 → 再次打开检查记录。

每一步结合以下问题复盘：

- 当前哪部分是真实实现，哪部分采用模拟提取？
- 为什么 16/20 的作业 A 贡献的是 24 分总评？
- 多项未知时，为什么不能直接给出唯一的期末分数？
- 实际成绩何时改变，预计成绩何时清空，取消保留什么？
- 哪些结果依赖假设，哪些规则会阻止正式计算？
- 下一项验证最需要补充哪种证据，它能回答什么问题？

演示步骤与取证方式见 [演示脚本](../docs/demo-walkthrough.md)。
