# 用本项目理解产品取舍

更新：2026-11-25。这是根据实际需求、实现与检查整理的复盘和面试自检素材，由 Codex 协助撰写。它不是发起人已经学习完毕或掌握全部技术的证明。讲述项目时，应只使用自己能结合代码、界面或实例解释的内容。

## 1. 缩短表单不一定解决任务问题

**实际发生：**发起人认为规则页面太长、术语难懂；将长表单拆为三步后，又指出核心诉求是从材料直接生成成绩页。最终新课程去掉手工建课前置，规则表单移到生成后的修正入口。

**可以学到：**界面是否简洁与任务是否省力是两个问题。若用户仍要抄写全部课程规则，三步表单也可能偏离任务。演示版可以先展示生成后核对与更新体验，但无法证明真实模型已经减少录入时间。

**自检：**为什么不直接删掉规则编辑？因为生成结果可能有错，需要纠正；问题在于它出现的时机和用途。

证据：[产品需求](../docs/product-requirements.md)、[导入界面](../dist/import-view.mjs)、[规则修正界面](../dist/rules-view.mjs)。

## 2. 模型输出有结构，不代表内容可靠

**实际决定：**独立实验 Prompt 要求权重、满分、实际/预计、额外及格要求和来源引用；缺失用空值，冲突保留各方信息，不支持的规则保留原文。

**具体例子：**材料写“期末占 50%”只能说明课程权重，不能推出期末满分 100，更不能推出期末最低分为 50%。一个合法 JSON 仍可能把这三件事混在一起。

**自检：**为什么不能让提取结果直接成为已确认规则？字段可能缺失、语义可能误读，且模型不能替学生核对课程材料。

当前只准备了 Prompt 与 5 个合成案例，未取得真实模型输出。这一节描述设计，不宣称已完成 Prompt 调优或提高提取准确率。

证据：[Prompt](../prompts/extract-rules.md)、[案例与人工答案](../evaluation/cases.jsonl)。

## 3. 实际、预计与未知必须分开

**实际实现：**实际成绩进入已取得的总评分；预计只用于试算；未出分保留为空。实际零分是已知结果，不能当作空白。

**具体例子：**作业 B 满分 40、占 20%，预计 30 时贡献 15 分；实际公布 32 后贡献 16 分。两者不能相加成 31 分贡献。确认实际成绩后清空该项预计，保留其他成绩。

**自检：**“按预计可以达标”和“当前已经达标”差在哪里？前者依赖尚未发生的假设；总分达标之后还可能有期末单独最低分要求。

证据：[状态设计](../docs/state-design.md)、[成绩编辑模块](../dist/score-edit.mjs)、[计算测试](../tests/calculation.test.mjs)。

## 4. 取消和保存失败也是产品行为

**实际实现：**编辑先放草稿，核对确认后提交；取消恢复原值。存储失败时保留当前页面修改并显示未保存，多标签变化暂停覆盖。开发检查发现“重试保存可能提前保存规则草稿”后，改为重试已接受的原记录。

**可以学到：**分数看起来变了不等于保存成功；确认按钮也不能让未核对的其他草稿一起生效。需要明确数据在什么时候被接受、什么时候能恢复。

**自检：**为什么修改已出成绩比调整预计多一步？已出成绩是后续计算依据，需要降低无意修改风险；预计是用于尝试的假设，需要便于反复调整。

证据：[导入与保护检查](../docs/verification-import-demo-2026-11-25.md)、[存储模块](../dist/storage.mjs)。该问题来自开发检查，不是线上事故。

## 5. 93 项检查能证明什么

**现有记录：**计算 52、存储 13、成绩编辑 11、应用事件 14、启动 3，合计 93 项。应用事件使用最小 DOM 和内存存储替身，并非完整浏览器。

**可以说明：**这些输入和边界下的模块与事件行为经过检查。不能说明模型准确率、真实浏览器全部可用、用户任务成功率或效率提升。

**自检：**为什么手工标准答案不能由同一计算程序生成？如果程序有系统性错误，自动生成的答案可能重复同样错误。为什么模拟生成不能当成模型实验？它没有真实模型输入输出。

后续需分别取得浏览器操作记录、真实模型首次输出与人工比对、同学任务观察。没有结果的表格保留未执行，不为了展示完整而补数字。

证据：[测试运行说明](../tests/README.md)、[模型实验说明](../evaluation/README.md)、[浏览器清单](../docs/browser-checklist.md)。

## 6. 如何诚实说明自己的工作

发起人可以说明自己提供了课程算分场景，确定了材料导入、持续更新、生成后修正与已出成绩保护等要求，并根据实际页面反馈推动流程调整。代码、测试、具体数据结构和本轮文档由 Codex 辅助完成，应明确这一分工。

准备面试时，先独立演示一遍：生成样例 → 预计 B 为 30 → 解释期末 72 → 实际 B 为 32 → 解释期末 70 → 修改后取消 → 再次打开。能讲清每一步的依据，比背诵技术名词更有说服力；尚未亲自完成的步骤保持待练习。
