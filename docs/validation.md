# 验证设计与已有证据

更新：2026-11-25。课程成绩规划 Demo 的验证重点是：学生能否从材料得到可核对的成绩表，理解目标要求，并在下一次出分后继续使用同一份记录。

**当前已有 93 项自动检查通过，以及部分本地浏览器操作记录。真实模型实验、同学观察和完整浏览器验收尚未完成。** 配套材料的“模拟提取”只用于演示流程，不计入模型质量结果。

## 1. 先明确要回答什么问题

| 产品问题 | 验证方法与通过标准 | 已有证据 | 还缺什么 |
| --- | --- | --- | --- |
| 生成成绩表后，能否直接开始核对和试算？ | 实际操作截图与文字入口；无需从空表逐项建课，生成后能修正 | 应用事件自动检查已覆盖；本地看过导入页 | 实际重新生成、替换和修正的浏览器记录 |
| 分数和目标要求算得对吗？ | 用独立手算答案比对；实际、预计、最低分和边界判断均符合计算契约 | 52 项计算检查通过 | 已覆盖范围之外不能外推 |
| 修改和保存会不会破坏旧成绩？ | 录入、取消、确认、刷新后检查本项与其他项；确认前不改变原记录 | 相关自动检查及部分实际浏览器操作通过 | 清除、重开、存储失败和冲突等浏览器路径 |
| 学生能否理解结果、完成二次更新？ | 让同学完成任务并解释结果，记录完成、误解和求助 | 已有发起人反馈用于改版 | 同学任务观察尚未开始 |
| AI 能否忠实提取课程规则？ | 固定 Prompt，保留首次回复，与人工答案逐字段比对 | Prompt 与 5 个合成案例已准备 | 真实模型输出、真实课程材料与错误分析 |
| 公开链接能否使用？ | 先核验资源可达，再独立操作生成、试算、改分和刷新 | Pages 已部署；首页及 12 个网页资源 HTTP 核验通过 | 线上实际交互验收 |

自动检查、本地浏览器操作、模型实验、同学观察和发布检查分别记录。它们回答不同问题，不合并成一个“产品准确率”。

## 2. 计算与更新：怎样证明结果正确

人工答案先按 [计算契约](calculation-spec.md) 独立算出，再与程序结果比较。不能让待测程序生成自己的标准答案。

### 一个贯穿演示的人工基准

合成课程：A 占 30%，满分 20，实际 16；B 占 20%，满分 40；期末占 50%，满分 100，且至少取得 50 分。个人目标为总评 75。

| 操作 | 应出现的结果 | 为什么要测 |
| --- | --- | --- |
| 只录入 A 实际 16 | 实际已获 24 分，还差 51 分；剩余最多贡献 70 分，整体约需 73% | 检查原始分与总评分的换算；整体要求不是每项必须取得 73% |
| B 填预计 30 | 实际已获仍为 24 分；按此假设，期末需 72/100 | 检查预计不会变成已获成绩 |
| B 确认录入实际 32 | 实际已获变为 40 分；期末需 70/100；B 的旧预计清空，A 仍为 16 | 检查实际替代本项假设，且不丢其他成绩 |
| B 拟改 31 后取消 | B 仍为 32；刷新后仍保留 A 和 B 的原记录 | 检查草稿不会提前改变正式记录 |

现有计算检查还覆盖会改变结论的边界，例如实际零分与未出分、总分够但单项最低分未达、目标不可达、预计越界、零权重项目仍有最低分要求，以及 49.9999 不能按显示舍入判为达到 50。具体基准与检查项见 [计算契约](calculation-spec.md) 和 [测试说明](../tests/README.md)。

## 3. 浏览器：怎样证明操作确实能完成

已有本地走查从一份**已存在的待核对演示课程**开始，没有重新生成课程。实际完成了规则确认、B 预计 30 后期末要求 72、预计刷新恢复、实际 32 的取消与确认、拟改 31 后 Esc 取消，以及实际刷新恢复。文字证据见 [浏览器走查记录](verification-browser-2026-11-25.md)。

| 尚待检查的路径 | 通过标准 |
| --- | --- |
| 截图／文字重新生成、自有材料预览 | 配套材料生成成绩表；自己的材料明确未识别，不出现无关样例答案 |
| 改名与规则修正 | 改名保留成绩；规则草稿保存后才生效，取消保留原规则；规则变化后重新核对 |
| 实际零分、清除及越界输入 | 零分不会变成未知；清除经确认；无效值指出具体问题 |
| 替换课程与再次打开 | 替换前确认，取消保留旧课程；同一浏览器和地址再次打开能恢复记录 |
| 保存异常与多标签冲突 | 显示未保存或冲突，不静默覆盖已有记录；重试不提交未确认草稿 |
| 键盘及不同窗口宽度 | 内容和操作可见；弹窗可用键盘完成或取消，焦点顺序可理解 |

执行步骤统一放在 [浏览器验收清单](browser-checklist.md)，实际通过一项才勾选一项。README 的横版主图用于展示界面，不代替刷新、取消或重新生成的操作证据。线上操作另行记录；[部署与资源可达记录](repository-release.md)不代表线上交互已经通过。

## 4. 同学观察：怎样检验设计是否帮到用户

**目前未开始，没有完成率、耗时改善或满意度结果。** 首轮可邀请 2—3 位同学，使用合成课程，观察以下任务。人数少时先展示每人的表现及原话，再汇总实际分子／分母。

| 观察任务 | 完成标准 | 需要记录的内容 |
| --- | --- | --- |
| 首次生成与核对 | 能找到样例入口、生成成绩表、核对规则并填写预计分数 | 是否求助、在哪一步停顿、能否说明这是模拟提取 |
| 二次更新 | 重新打开已有课程，录入新实际成绩，读出更新后的目标要求 | 是否重复输入旧信息、是否误改其他成绩、完成时间 |
| 取消与确认修改 | 取消后原值保留，确认后仅本项改变 | 能否找到修改入口、是否理解何时生效、是否误清其他记录 |
| 解释结果 | 能区分实际与预计、整体要求与单项分数、总分目标与额外及格条件 | 各题回答、误解位置和求助；不能只记录“觉得好用” |

任务完成情况按“独立完成／求助后完成／未完成”记录；如报告完成率，明确是否包含求助。结果理解按题记录正确人数／回答人数，不能把不同题混成一项未经定义的分数。

若比较持续记录与原有聊天算分流程，使用难度匹配的材料和任务，并让双方保留可用的历史信息。首次整理与二次更新分别计时，记录先后顺序。只有实际观察后才能讨论节省时间；少量同学表现不能推出普遍需求或长期使用效果。

首次使用只评价生成后的交互理解，不将预置样例瞬间返回与真实模型等待时间比较成“提取更快”。二次更新可比较实际的改分、计算和理解过程，并说明 Demo 使用模拟提取。

## 5. 模型提取：怎样检验 AI 是否可信

网页尚未调用模型。独立实验可以在已有对话工具中手工提交 [固定 Prompt v0.1](../prompts/extract-rules.md)，不要求先接 API。操作和输入边界见 [实验说明](../evaluation/README.md)；[5 个合成案例](../evaluation/cases.jsonl)全部为 `not_run`，没有真实模型结果。

每例先保留首次原始回复，再核对字段与来源；追加提示后的回复和人工修正另记。真实原件、同源改写和合成案例分别统计；同一张截图的文字改写不算另一门独立课程。

| 要判断的问题 | 核对标准与记录方法 |
| --- | --- |
| 关键字段是否正确？ | 权重、原始满分、实际／预计、通过线、目标及最低分逐字段对照；报告正确字段数／标注字段数和整例正确数／已运行案例数 |
| 输出是否有依据？ | 每个非空事实字段的引用能支持该值；记录支持字段数／输出非空事实字段数，并逐项列出无依据新增信息 |
| 缺失和冲突是否被保留？ | 缺少满分就留空并询问；40% 与 50% 冲突就保留两份来源；不猜默认值或自动选一方 |
| 特殊规则是否被误改？ | 严格大于不能改成大于等于；去掉最低成绩不能当普通加权；保留原文并标为暂不支持 |
| 能否进入核对环节？ | 结构和类型正确，完整材料仍输出待核对候选；格式通过与内容正确分别记录 |

比较时允许等价十进制表达，严格区分空值与零、原始分与百分比、`>` 与 `>=`。最低分遗漏、实际／预计混淆、无依据补值、覆盖冲突、丢弃特殊规则或越过用户确认，都应逐例列出；总字段正确率高也不能掩盖这些问题。某类问题分母为零时记为“不适用”。

已有案例分别覆盖完整材料、缺满分、来源冲突、严格大于和去掉最低成绩。真实材料及人工核对答案仍待补充。没有实际输出就不能把这些预期写成失败案例或准确率；模型实验有结果后，也不能据此宣称网页已接入模型。

## 6. 下一步补证据的顺序

1. 在可用且获准的浏览器环境补齐生成、修正、更新和保存异常的验收，单独记录本地与线上结果。
2. 观察同学完成二次更新与结果解释；根据实际误解调整交互，再用同一任务复测。
3. 取得真实课程材料和可用模型工具后执行独立实验，保存输入、Prompt 版本、模型可见名称、首次输出及人工比对。耗时和成本只记录实际可取得的数据。

浏览器、同学观察与模型实验可按资源并行推进。缺少 API 不阻止演示验收；缺少同学观察不妨碍如实展示已有功能与计算证据。
