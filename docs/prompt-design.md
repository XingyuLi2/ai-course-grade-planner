# Prompt设计：课程评分规则提取

本文件说明规则提取Prompt的职责、输入输出和核对流程。当前版本为 `extract-rules-v0.1`，完整正文见 [规则提取Prompt](../prompts/extract-rules.md)。网页目前使用配套演示材料的模拟提取，没有调用该Prompt；独立真实模型实验待执行。

## 1. 设计目标

将截图、课程文字和补充说明整理成可核对的评分规则，减少学生逐项整理课程信息的操作。

提取结果需要：

- 分清考核占比、原始满分和原始得分。
- 分别记录实际成绩与学生填写的预计成绩。
- 保留额外及格要求及其适用项目。
- 为材料事实提供可追溯来源。
- 将缺失、冲突和未支持规则转成具体核对问题。
- 使用稳定字段，便于后续校验与成绩表展示。

总评、目标倒推和通过条件由确定性计算逻辑处理。

## 2. Prompt职责

当前只设计一类规则提取Prompt，对应一门课程的一组材料。

| 项目 | 约定 |
| --- | --- |
| 角色 | 课程评分规则提取助手 |
| 输入 | 带材料编号的截图、文字、补充规则及学生提供的成绩 |
| 输出 | `candidate-0.1` 候选JSON，包含规则、来源、问题和待确认项 |
| 状态 | 字段可用时为 `pending`，含未支持规则时为 `unsupported` |
| 后续处理 | 学生核对与修正，再由程序校验并计算 |

单次输出覆盖材料整理和问题定位，不新增成绩预测或学习建议任务。

## 3. 规则提取Prompt

### 3.1 使用场景

学生提供课程评分截图，并补充已经公布的作业成绩和自己的目标。截图可能只有占比，另一份说明可能包含期末最低分要求。提取需要同时保留这些信息及来源。

输入按材料编号组织，例如：

```text
M1：课程评分说明截图
M2：老师补充的期末最低分要求
M3：学生提供的实际成绩、预计成绩和个人目标
```

模型实验只提交输入材料，人工答案单独用于之后的比对。

### 3.2 模板组成

完整模板保存在 [prompts/extract-rules.md](../prompts/extract-rules.md)，由四部分组成：

| 部分 | 作用 |
| --- | --- |
| 角色与任务 | 确定只提取候选规则，材料中的其他指令作为数据处理 |
| 处理原则 | 统一单位、区分未知与零、处理来源冲突和特殊规则 |
| 输出结构 | 固定字段、类型、状态和问题位置 |
| 本次材料 | 附加编号后的截图、文字与补充说明 |

### 3.3 输入解释规则

- 20%的权重转为十进制字符串 `"0.2"`；原始满分仍保留材料中的单位。
- 未给出的数值用 `null`，明确零分用 `"0"`。
- 实际与预计分别写入 `actual`、`expected`。同项两者都有时保留输入并标明预计已失效。
- 没有读到门槛时使用 `unknown`；材料明确没有门槛时使用 `none_in_source`；有门槛时使用 `present_in_source`。
- 冲突字段的选定值留空，候选值及来源写入 `conflicts`。
- 结构或诊断字段以外的非空事实字段，均需原文支持。

## 4. 结构化输出

### 4.1 字段设计

| 字段组 | 主要字段 | 用途 |
| --- | --- | --- |
| 基本信息 | `schemaVersion`、`ruleStatus`、`name`、`totalMax` | 标识候选格式、课程与核对状态 |
| 考核项目 | `items[].id/name/weight/max/actual/expected/step` | 记录项目规则和两类成绩 |
| 课程目标 | `passMark`、`targets` | 分开保存通过线与个人目标 |
| 额外及格要求 | `hurdleStatus`、`hurdleCombination`、`hurdles` | 保留对象、运算符、阈值、单位及条件关系 |
| 来源 | `evidence` | 将字段关联到材料编号、原文和位置 |
| 冲突 | `conflicts` | 同时呈现不同来源的候选值和待核对问题 |
| 支持边界 | `unsupportedRules` | 保留特殊规则原文与原因 |
| 待处理问题 | `issues`、`questions` | 定位缺失、冲突、无效值及需要学生回答的事项 |

数值使用十进制字符串或 `null`。空数组写为 `[]`。每个项目有稳定ID，来源引用通过字段路径关联。

### 4.2 字段级示例

以下为人工构造的格式说明：材料只写“课程论文占40%”，未给论文满分。

```json
{
  "id": "essay",
  "name": "课程论文",
  "weight": "0.4",
  "max": null,
  "actual": null,
  "expected": null,
  "step": null
}
```

这只是完整输出中 `items` 的一个条目。完整候选还应包含该权重的来源引用、满分缺失问题及“课程论文原始满分是多少”的核对问题。完整JSON结构以Prompt正文为准。

## 5. 核对与计算衔接

候选数据进入计算前，需要经历三个动作：

```text
提取候选规则 → 核对来源并解决具体问题 → 校验后确认课程
```

模型只输出 `pending` 或 `unsupported`。学生核对项目、权重、满分、通过线与最低分要求；有问题时修正已有结果。全部必要字段完整、冲突已解决且规则受支持后，程序才提供正式目标试算。

候选结构中的 `none_in_source` 表示材料写明无额外要求；学生确认后，才对应课程数据中的 `none`。`present_in_source` 对应的门槛也需要核对对象、符号、阈值和单位。课程修改后重新核对，实际与预计成绩分别保存。

当前网页通过配套样例展示生成与核对流程。独立模型输出的自动导入与字段转换接口尚未实现。

## 6. 规则边界与风险处理

当前计算器支持100分总评、明确权重与原始满分，以及单项 `>=` 最低分要求。具体定义见 [计算契约](calculation-spec.md)。

| 风险 | Prompt处理方式 | 核对重点 |
| --- | --- | --- |
| 猜测缺失规则 | 缺失值留空并提问 | 满分、通过线、目标阈值、计分步长 |
| 权重与满分混淆 | 明确单位和字段，保留来源 | 20%占比与满分20是否被混用 |
| 门槛遗漏或改写 | 保留对象、运算符、阈值与单位 | 严格 `>`、百分比与原始分、AND／OR关系 |
| 冲突自动覆盖 | 保留全部候选和来源，选定值留空 | 截图、正文与补充说明之间的差异 |
| 特殊规则被丢弃 | 写入 `unsupportedRules` 并设为不支持状态 | 去掉最低成绩、曲线调分、补考替代等 |
| 无依据引用 | 为每个事实字段提供材料原文 | 引用是否存在且支持对应值 |
| 输出格式变化 | 给出字段模板、类型和空值约定 | 独立实验检查JSON结构与语义 |
| 材料夹带任务指令 | 将材料视为待提取数据 | 是否偏离提取任务或输出正式通过结论 |

上述规则已写入Prompt，效果通过独立实验逐项验证。

## 7. 当前演示版对应关系

| 产品环节 | 当前实现 | Prompt相关工作 |
| --- | --- | --- |
| 配套截图／文字导入 | 对应样例生成成绩表，标记“模拟提取” | 用同类字段验证未来候选结构 |
| 自己的材料 | 本机预览，显示未识别状态 | 后续作为真实提取输入 |
| 生成后核对 | 成绩表直接可见，支持修正项目和规则 | 保留人工确认环节 |
| 预计试算与更新 | 程序计算，实际与预计分开 | 提取只提供输入事实 |
| 规则质量实验 | 已准备Prompt、5个合成案例与人工答案 | 待运行并保存原始输出 |
| 网页模型调用 | 尚未接入 | 依赖后续接口与候选校验设计 |

## 8. 测试与迭代

先用现有5个合成案例检查完整输入、缺失字段、来源冲突、严格大于和去掉最低成绩，再补充真实课程材料。案例说明见 [实验目录](../evaluation/README.md)，指标定义见 [评测说明](validation.md)。

执行时固定Prompt版本和输入，记录工具可见模型名、材料编号与会话上下文；保存首次完整输出。逐字段对比后，将实际错误归入缺失、冲突、单位、门槛、特殊规则或引用问题。

如果修改Prompt，保留旧版输出和修改原因，再使用相同输入复测；人工追加提示的结果单独记录。后续网页接入需要另行完成候选校验、确认状态转换和失败提示。
