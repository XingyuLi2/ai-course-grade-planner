# 课程成绩计算契约

> 状态：公开版计算契约。公式与12个人工基准用于实现和验收；已执行检查及边界见 [验证说明](validation.md)，文档本身不等于所有路径已验收。
> 更新日期：2026-11-25。
> 本文的默认值是为本项目提出的产品约定，不代表任何学校的评分政策。所有算例均为人工构造，**不是任何学校的真实规则或成绩**。
> 产品提供两种计算：根据实际成绩查看剩余考核的整体要求；填写部分预计成绩后，倒推唯一未知项或其余未设定项目的要求。

## 1. 适用范围与规则确认

首版只计算课程总评为 100 分、考核项目以明确权重加权、每项有明确原始满分的课程；支持明确的单项 `>=` hurdle（最低分要求）。目标分数、通过分数线、权重和 hurdle 均来自用户确认的材料，不根据学校、课程代码或 P／D／HD 标签猜测。

规则须分为三种状态：

| 状态 | 含义 | 可提供的结果 |
| --- | --- | --- |
| 已确认且受支持 | 必要字段完整，材料矛盾已解决，所有影响计算或通过的规则都在支持范围内 | 按本契约输出计算和条件判断 |
| 待确认 | 缺失、含义不清、来源冲突，或用户尚未确认 | 保存草稿并说明缺什么；不输出确定的通过结论或正式目标倒推结果 |
| 暂不支持 | 明确存在首版不能处理的规则 | 保留原文并说明原因；不删除该规则后继续给出正式结果 |

以下规则不在首版支持范围内：严格大于 `>` 的 hurdle、调分曲线、成绩封顶、去掉最低若干次成绩、补考替代、加分导致成绩超过原始满分，以及复杂的 OR／组合通过条件。发现这类规则时，不将其改写成普通加权或 `>=`。相同字段在截图、正文与补充说明中冲突时，交给用户解决；不按材料顺序或模型猜测自动覆盖。

用户明确确认的 `>=` hurdle 是计算的约束，优先于“加权总分已足够”的判断。这里的“优先”不表示用户未确认的补充文字自动覆盖冲突材料。

“材料里没读到 hurdle”必须记录为**待确认**，不能自动等同于“明确无 hurdle”。用户确认没有额外门槛后，才能将 hurdle 集合设为空并正常判断。

## 2. 输入数据及校验

每个考核项目有唯一标识，并至少包含以下字段：

| 字段 | 数学约定 | 输入要求 |
| --- | --- | --- |
| 权重 `w_i` | `0 <= w_i <= 1`，所有项目的权重之和为 `1` | 输入的 `20%` 转成 `0.2`；不把 `20` 当成内部权重，不自动归一化缺失或异常权重 |
| 原始满分 `m_i` | `m_i > 0` | 必须知道具体满分；不能把未知满分默认为 100 |
| 实际成绩 `a_i` | 空值，或 `0 <= a_i <= m_i` | 空值表示未出分；`0` 是已出分的零分，两者不可互换 |
| 预计成绩 `p_i` | 空值，或 `0 <= p_i <= m_i` | 仅用于未有实际成绩的项目；与实际成绩使用相同原始单位 |
| 原始成绩步长 `s_i` | 可不设置；若设置则 `s_i > 0` | 只在材料或用户明确确认计分粒度后设置，例如每 1 分或每 0.5 分；不猜测学校规则 |

课程还需要：

- 一个或多个用户确认的目标分数 `T`，均在 `[0, 100]` 内。每个目标独立计算。
- 若要判断“通过课程”，必须有已确认的通过总评分数线 `P`，且 `0 <= P <= 100`。P／D／HD 等名称只是标签，不能替代具体阈值。
- 明确的 hurdle 状态：已确认无门槛，或已确认的门槛列表，或待确认。每条门槛需给出对象、`>=` 运算符、阈值及单位。

校验以输入十进制数的实际含义为准。权重 `0.2 + 0.3 + 0.5` 合计为 `1`；合计 `0.9999` 不等于 `1`，需要用户确认，不自动补齐或缩放。实现需避免二进制浮点误差造成误判，但不能用宽松容差把真正低于分数线的成绩判为达标。

当设置步长时，首版约定可得原始成绩为从 `0` 开始的 `s_i` 整数倍，并要求满分也是步长的整数倍。与步长冲突的实际／预计分数、或不能被步长整除的满分，需要用户确认，不能静默四舍五入。若课程采用其他计分集合，标为待确认或暂不支持。

## 3. 实际成绩与预计成绩的优先级

两种输入分开保存和标记，任何一次计算中同一项目只能贡献一次分数。

1. **实际成绩存在时，以实际成绩为准。** 界面不再让该项预计成绩参与试算；正式确认录入实际成绩时清空该项预计值，保留其他项目的实际与预计值。录入／修改／清除前先编辑并核对，取消保留原值。
2. 如果旧记录或导入数据同时含实际值与预计值，计算只使用实际值，并提示预计值已失效；不相加、不平均，也不把预计值反写成实际值。
3. 实际成绩为空、预计成绩有值时，只在模拟中使用预计成绩。
4. 两者都为空时，该项是未知项。清空实际成绩后，该项回到未知状态，不自动恢复旧预计值。

提供两个互不混淆的计算视角：

| 视角 | 固定成绩 | 未知项 | 结果性质 |
| --- | --- | --- | --- |
| 剩余整体要求 | 只使用实际成绩 | 所有未出实际成绩的项目；忽略其预计值 | 根据当前实际记录的数学要求 |
| 预计成绩试算 | 先取实际成绩；无实际成绩时取预计成绩 | 实际、预计均为空的项目 | 依赖列明的预计成绩假设 |

界面中的“实际已获得总评分”在两个视角下均只由实际成绩计算。若预计成绩改变，这个值不得变化。

2026-11-25 实施补充：校验也遵循视角。未出分项的无效预计（例如满分 40 却填 41）阻止预计试算，但不阻断忽略它的实际视角；页面保留有效实际概览。已有实际成绩时，残留预计即使无效也只提示失效，不覆盖或阻断实际计算。网页的最终规则确认与规则修正提交会校验规则及实际成绩，不以无效预计阻断确认；预计输入仍在依赖它的试算中校验。底层校验函数默认包含预计检查，网页确认入口明确排除预计，两者不能混同。

## 4. 基础换算与总评分

对有固定成绩 `x_i` 的项目：

```text
单项得分率 q_i = x_i / m_i                 （0..1）
单项得分百分比 = 100 × q_i                 （0..100%）
单项贡献 c_i = 100 × w_i × q_i             （课程总评分，满分 100）
```

例如原始满分 60、实际得分 45、权重 20%，单项得分率为 75%，贡献为 `100 × 0.2 × 45 / 60 = 15` 个课程总评分。

设 `A` 为所有实际成绩已知的项目，`E` 为只有预计成绩的项目：

```text
实际已获得总评分 S_actual = Σ(i∈A) 100 × w_i × a_i / m_i
预计贡献 S_expected = Σ(i∈E) 100 × w_i × p_i / m_i
```

- 基础视角的固定贡献 `S = S_actual`。
- 模拟视角的固定贡献 `S = S_actual + S_expected`。
- `S_actual` 是已经贡献给整门课的分数，不能命名为“已完成考核的平均分”，也不能将预计贡献混入。
- 仍有正权重未知项时，`S` 不是已确定的最终总评。

## 5. 剩余整体要求

在当前视角中，设 `U` 为未知项集合，`W = Σ(i∈U) w_i`，目标为 `T`：

```text
距目标的差额 Δ = T - S
总评还需贡献 D = max(0, Δ)
当前固定成绩／假设下的最高可能总评 M = S + 100 × W
```

当 `W > 0` 时：

```text
仅由总分目标产生的原始要求 r_raw = Δ / (100 × W)
用于展示的最低加权得分率 r = max(0, r_raw)
所需加权得分百分比 = 100 × r
```

输出同时明确两个单位，例如“总评还差 15 分；剩余考核权重为 30%；这些考核合计需要达到 50% 的加权得分率”。

边界处理：

- `Δ <= 0`：总分目标的额外要求为 0，但仍检查所有 hurdle。不得表述为“后续都考 0 分也一定通过”。
- `0 < Δ <= 100 × W`：总评分目标在数值上可达；**不等于通过条件一定可满足**。
- `Δ > 100 × W`：总评分目标不可达；模拟视角必须写“按当前预计成绩假设无法达到”，不能扩展为现实中必然无法达到。
- 多个未知项时，`r` 是以课程权重加权的整体要求，不是各项原始分数的简单平均，也不是每项都必须达到该百分比。
- 首版不会从多个未知项推导唯一的分数组合。未知项目各自的 hurdle 另列，不由整体得分率替代。
- 最高可能总评 `M` 仅描述加权总分的上限；即便 `M` 高于目标，已有实际 hurdle 失败时仍不能通过课程。

## 6. 只有一项未知时的倒推

若未知项仅有 `j` 且 `w_j > 0`：

```text
总分条件所需的原始成绩 x_total = max(0, Δ) × m_j / (100 × w_j)
```

若该项有已确认 hurdle，先统一为原始分数阈值 `h_j`；多条都必须满足的同项 `>=` 门槛取最高阈值。没有门槛时 `h_j = 0`。两种来源须分开展示：

```text
总分条件：至少 x_total / m_j
该项 hurdle：至少 h_j / m_j（若存在）
两者同时满足的数学下界 x_min = max(x_total, h_j)
```

- `x_min > m_j` 时不可达，不能将要求截断为满分后称为可达。
- 其他项目有实际 hurdle 失败时，即使 `x_min` 在范围内，也不能宣称“考到该分数即可通过”。此时可以显示总分目标的计算值，但通过状态必须明确为不满足。
- 其他项目的预计成绩低于其 hurdle 时，必须说明“当前假设违反门槛”；不得暗示提高唯一未知项就能弥补。
- 只有唯一未知项确实是期末时，结果才能命名为“期末需要多少分”。
- 如果还有其他未知项，即使其权重为 0，也不能隐藏其独立门槛或将其视为已完成。

## 7. hurdle 与通过／目标状态

### 7.1 门槛表达

每条受支持的 hurdle 指向一个考核项目，形式为以下之一：

```text
原始分数 >= h                 （h 与该项满分使用相同单位）
单项得分百分比 >= H%          （转换为原始分数 h = m_i × H / 100）
```

阈值须在可得分数范围内。`>=` 包含恰好等于阈值的情况；`> 50%` 不得当作 `>= 50%`。多条门槛仅在材料明确要求全部同时满足时按 AND 检查；不自行推测组合逻辑。

### 7.2 单条门槛状态

| 数据情况 | 状态与用语 |
| --- | --- |
| 有实际成绩且达到阈值 | 实际已满足 |
| 有实际成绩且低于阈值 | 实际未满足；按当前支持规则无法靠其他项分数补偿 |
| 无实际成绩，模拟中有预计成绩且达到阈值 | 按预计成绩满足，尚未实际达成 |
| 无实际成绩，模拟中有预计成绩且低于阈值 | 当前预计成绩假设不满足 |
| 无可用成绩，门槛本身明确 | 门槛待取得成绩验证；同时列出其要求 |
| 门槛是否存在或含义尚不明确 | 规则待确认；不输出确定的通过结论 |

### 7.3 课程结果必须分别呈现

至少分开报告：**总评目标、每项 hurdle、是否仍依赖预计／未知成绩**。不得把它们压成一个不带条件的“通过”。

- 判断通过课程，需要 `总评 >= P` 且全部已确认 hurdle 满足。
- 检查目标 `T` 使用其自身阈值。`T < P` 时，即使目标达成也不能因此判断通过。
- `S_actual >= T` 可以表述为“实际成绩已贡献足够的总评分达到目标”；若仍有未出分项，不称为已获得官方最终总评或等级。
- 只有实际成绩已贡献足够的通过总评分、所有 hurdle 都由实际成绩满足、且规则已完整确认时，才可写“按已确认规则，当前实际成绩已满足通过条件”。
- 由预计成绩提供的达标或门槛满足必须写“按当前假设满足”。仍有未知项时，输出要求／条件，不称为预测已通过。
- 若已经有一条实际 hurdle 失败，实际失败状态优先于总评分可达和所有模拟结果；不能用预计成绩覆盖该实际成绩。补考等修复机制不在首版内。
- 已全部出分且总评低于 `P`，或存在实际失败的 hurdle，写“按已确认规则未满足通过条件”；未出分、总评目前不足但仍可达时，写“尚待后续成绩”，不能提前宣判不通过。

## 8. 没有剩余权重时

`W = 0` 时禁止计算 `Δ / (100 × W)`，也不能显示 `NaN`、无穷大或伪造的“剩余需要 0%”。

- 若 `S >= T`：总分目标已被当前固定成绩／假设满足，显示对应的实际或模拟性质。
- 若 `S < T`：按当前固定成绩／假设，总分目标无法再通过未知项改变。
- 若全部成绩均为实际值，显示实际总评及其条件检查。
- 若固定成绩含预计值，显示模拟总评及假设，不称其为实际总评。
- `W = 0` 不一定表示所有成绩均已知：零权重项目也可以有 hurdle。该项若未出分，仍需列出门槛并标为待验证；不能因分母为零就宣称通过。
- 唯一未知项权重为 0 时，总分不因它改变，但仍可明确显示其 hurdle 所需原始成绩。不得套用单项倒推的除以权重公式。

## 9. 小数显示与可得分步长

数学计算、阈值比较与界面显示必须分开：

1. 内部保留足够的准确性；不先把单项贡献、百分比或总评分取整再计算。
2. 总评 `49.9999` 不能因为显示为 `50.00` 就判定达到 50。临界状态需要显示足以解释判断的数字。
3. 最低要求不得向下取整后仍标“达到该值即可”。具体分数要求默认向上保留四位小数；多项剩余考核的整体百分比向上取整显示，并注明取整。该卡片优先展示还差的总评分 `max(0,T-S)`，同时列出剩余最多可贡献的总评分 `100×W` 与整数百分比。这些分数按权重折算，不是卷面分直接相加；显示取整不代表学校按整数计分，也不参与后续计算。
4. 未确认原始计分步长时，不自动假设整数分。给出数学下界，并说明实际可取得的分值需按课程规则确认。
5. 若已确认原始成绩步长 `s_j`，用下式得到满足下界的最小可得分值：

```text
x_step = ceil(x_min / s_j) × s_j
```

`ceil` 是向上取整，不是四舍五入或向下取整。再次检查 `x_step <= m_j`，并将该值代入原始公式与 hurdle 复核。步长作用于原始成绩，不作用于课程总评分或百分比。

显示所需百分比时，先从准确的数学值或已确认步长下的原始分数换算，不从已显示的四位小数字符串继续计算。

## 10. 人工验收算例

以下 `P = 50`、`D = 75` 等值均为**合成测试设置**，不是任何学校的规定。未特别说明时，所有规则均已确认；成绩步长未设置；没有列出 hurdle 的算例设为“用户已明确确认无 hurdle”。

### 例 1：不同满分换算，期末 hurdle 比通过总分要求更高

- 作业 A：权重 `0.2`，满分 60，实际 45。
- 作业 B：权重 `0.3`，满分 100，实际 80。
- 期末：权重 `0.5`，满分 100，未知；hurdle 为期末 `>= 50%`。
- 实际贡献：`15 + 24 = 39`；剩余权重 `0.5`；最高可能总评 `89`。
- 目标 P 50：总评还差 `11`，总分要求为期末 `22/100`；结合 hurdle，实际应显示至少 `50/100`。若期末取得 50，总评为 `64`。
- 目标 D 75：总评还差 `36`，期末需 `72/100`；比 hurdle 高，最终数学下界为 `72/100`。
- 当前期末未出分，不得显示实际已通过。

### 例 2：多个未知项，只能给整体加权要求

- A：权重 `0.3`，满分 20，实际 16；B：权重 `0.2`，满分 40，未知；期末：权重 `0.5`，满分 100，未知，hurdle 为 `>= 50%`。
- 目标 75；实际贡献 `24`；剩余权重 `0.7`；还差 `51`；最高可能总评 `94`。
- 剩余加权得分率为 `51 / 70 = 72.857142857…%`；主界面显示“还差51分总评，剩余最多贡献70分，约73%（向上取整）”。四位精度的数学值仍为 `72.8572%`，不参与显示后的再计算。
- 不能据此写“期末需要 72.8572 分”，也不能要求 B 和期末必须各得此百分比。
- 可人工验证一种达成组合：B `30/40`、期末 `72/100`，贡献 `15 + 36`，总评 `75`，期末 hurdle 也满足。这只是一个组合。

### 例 3：填写预计成绩，再由真实成绩替换

- 沿用例 2，给 B 填写预计 `30/40`。
- 基础视角仍是实际贡献 `24`、剩余整体要求 `72.857142857…%`；不因预计成绩改变。
- 模拟视角：预计贡献 `15`，固定贡献 `39`，未知权重 `0.5`；期末需 `72/100`；模拟最高可能总评 `89`。
- B 实际出分后录入 `32/40`：该项实际贡献变为 `16`，预计 30 失效；实际贡献合计 `40`，期末需 `70/100`。
- 不得得出 `24 + 15 + 16 = 55`；这会重复计算 B。

### 例 4：按实际成绩，目标已不可达

- A：权重 `0.6`、满分 100、实际 40；期末：权重 `0.4`、满分 100、未知。
- 目标 75；实际贡献 `24`，还差 `51`；剩余需 `127.5%`；最高可能总评只有 `64`。
- 显示按当前实际成绩无法达到该目标，不把要求截断成 100% 后称为可达。

### 例 5：仅当前模拟不可达，不扩大为实际必然不可达

- 沿用例 2，给 B 填写预计 `0/40`。
- 模拟固定贡献为 `24`，唯一未知是期末，权重 `0.5`；目标 75 需要期末 `102/100`，模拟最高总评 `74`。
- 显示“按 B = 0/40 的假设，目标不可达”。基础视角的最高可能总评仍为 `94`，目标在总分上仍可达。
- 预计零分是有效假设，不能当作空白忽略。

### 例 6：实际总分足够，但实际 hurdle 已失败

- A：权重 `0.4`，满分 100，实际 100；期末：权重 `0.6`，满分 100，实际 45。
- 通过线 50；期末 hurdle 为 `>= 50%`。
- 实际总评为 `40 + 27 = 67`，剩余权重为 `0`。
- 总评条件满足，但期末 `45 < 50`，实际 hurdle 未满足，课程通过条件不满足。不能输出“已通过”，也不能以其他项高分抵消该门槛。
- 即使记录残留期末预计 60，也必须使用实际 45，不能生成通过预测。

### 例 7：所有项目已填，但部分只是预计

- A：权重 `0.4`、满分 100、实际 80；期末：权重 `0.6`、满分 100、预计 50、实际为空。
- 通过线 50；期末 hurdle 为 `>= 50%`。
- 实际贡献为 `32`，预计贡献为 `30`；模拟总评为 `62`，模拟未知权重为 `0`。
- 结果为“按当前假设，总评及期末门槛满足通过条件”；不得称实际已通过，也不再计算模拟剩余百分比。
- 将期末预计改为 40 后，模拟总评为 `56`，虽然总分仍足够，但预计 hurdle 失败，不能显示模拟满足通过条件。

### 例 8：全部为实际成绩，恰好达到 hurdle

- 沿用例 7，将期末 50 改为实际成绩，清空预计值。
- 实际总评为 `62`，无剩余权重；期末 `50 >= 50`，所以按已确认规则实际通过条件满足。
- 对目标 75，实际总评未达标且无剩余可改变部分；不计算剩余要求，也不显示无穷大。

### 例 9：实际零分和未知成绩不同

- A：权重 `0.4`、满分 100、实际 0；期末：权重 `0.6`、满分 100、未知；目标 50。
- 实际零分已经固定，剩余权重为 `0.6`；期末需要 `83.333333333…/100`。
- 如果 A 和期末都未出分，剩余权重应为 `1`，整体只需 50% 的加权得分率。两种输入不能产生相同结果。

### 例 10：剩余权重为零，但仍有未知 hurdle

- A：权重 `1`、满分 100、实际 80；口试：权重 `0`、满分 10、未知。
- 通过线 50，目标 75；口试 hurdle 为原始成绩 `>= 5`。
- 实际总评分已为 `80`，未知权重为 `0`，不能再除以剩余权重；最高可能总评也是 `80`。
- 总分目标已足够，但口试门槛待实际成绩确认，不能显示已经通过。可直接显示“口试至少 5/10”，这来自门槛，不来自总分倒推。
- 若填口试预计 5，只能显示按假设满足；实际录入口试 5 后才是实际门槛满足。

### 例 11：数学下界与整数步长向上取整

- A：权重 `0.4`、满分 100、实际 70；期末：权重 `0.6`、满分 50、未知；目标 75。
- 期末 hurdle 为 `>= 50%`，即原始分数至少 25。
- 实际贡献 `28`；还差 `47`；期末总分要求为 `47 × 50 / 60 = 235/6 = 39.166666666…`。
- hurdle 更低，数学下界仍为 `39.166666666…/50`，所需单项百分比为 `78.333333333…%`。
- 未确认步长时，显示数学下界，不擅自写“必须 40 分”。
- 若用户明确确认期末以 1 分为步长：`ceil((235/6)/1) × 1 = 40`。代入得总评 `28 + 100 × 0.6 × 40/50 = 76`，满足目标及 hurdle。
- 向下取 39 会得到总评 `74.8`，不能声称满足 75。

### 例 12：显示四舍五入不能改变通过结论

- 唯一考核权重为 `1`、满分 100、实际成绩 `49.9999`；通过线 50；已明确无 hurdle；未设置成绩步长。
- 实际总评 `49.9999 < 50`，未满足通过总分条件。
- 即使一般显示保留两位小数，判断仍不得变成通过；应显示足够位数解释临界差距。

## 11. 非正常输入与规则验收清单

以下为输入和状态检查，不属于额外功能：

| 输入或情形 | 预期处理 |
| --- | --- |
| 权重合计 0.9、1.1 或 0.9999 | 要求确认，不自动归一化后计算 |
| 满分未知、为 0 或负数 | 要求补全／修正，禁止除法 |
| 实际或预计成绩小于 0、超过满分 | 标为无效；若来自额外加分等规则，转为待确认／暂不支持 |
| 目标小于 0 或大于 100 | 要求修正，不按正常百分制目标处理 |
| 只写“期末有 hurdle”，无阈值或单位 | 规则待确认，不猜 50% |
| AI 未提取出 hurdle，用户尚未确认有无 | 仍待确认，不当作明确无门槛 |
| 用户已确认没有 hurdle | hurdle 集合为空，可以按总评条件判断 |
| 材料写期末严格 `> 50%` | 标为暂不支持，保留原文；不能改为 `>= 50%` |
| 材料写去掉最低一次 quiz、补考替换等 | 标为暂不支持，保留原规则，不悄悄忽略 |
| 图中门槛 40%，补充文字 50%，尚未确认 | 展示冲突并要求用户解决，不自动决定 |
| 全部正权重项目已有固定成绩 | 不计算剩余除法；继续检查是否混有预计值、是否还有零权重 hurdle |
| 实际 hurdle 失败，但总分目标仍可达 | 总分条件与失败门槛分开展示，整体不得显示可通过 |
| 原始成绩步长为 1，但实际输入 39.5 | 要求确认数据或步长，不自动改成 39 或 40 |

## 12. 实现与验收约束

- 两种视角分别计算；预计值不能改变实际已获得分数。
- 所有公式沿用原始满分、比例权重和 100 分总评的统一单位。
- 对每个目标分别输出差额、剩余权重、总分要求及可达性；同时保留独立 hurdle 状态。
- 实际、模拟、未知、规则待确认的含义在结果中可见，不用一个“通过”标签替代。
- 未知成绩不填零；零权重不意味着无门槛；分母为零有独立分支。
- 正式结果只依据用户确认的受支持规则；不支持的内容不可在提取或计算环节静默丢失。
- 以上算例的自动检查结果见 [测试说明](../tests/README.md)；本文预期值来自独立手算关系，不能用待测实现自身输出覆盖标准答案。
