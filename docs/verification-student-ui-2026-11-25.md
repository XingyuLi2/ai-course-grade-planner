## 真实输入

项目发起人报告页面过长、重点不清，以及“计分步长”“通过总分与目标”“独立门槛（hurdle）”“AND”难理解；随后要求必要术语在对应位置下方加一句解释。用户附了旧版页面截图，未报告完整保存/试算任务结果。本轮不把这份反馈当作同学任务观察或完整浏览器验收。

## 实际改动

- 设置页改为“考核与占比 / 及格线和目标 / 额外及格要求”三个步骤；只显示当前一步，材料和选填项折叠，底部固定操作入口并预留内容空间。
- 给分单位解释整数分与半分，未知时留空；有已填单位或来源时，折叠摘要有标记。已有问题和特殊规则会展开，不丢失旧数据。
- 用“这门课总评多少分算及格”“你想拿到多少分”“课程有这样的要求吗”等表达，给最低分要求配50/100的例子和课程材料来源说明。
- 总评、占总评比例、加权得分率保留必要含义，并在附近加一句解释。严格超过与至少达到仍分开，不改变计算规则。
- 成绩页一次显示选中的目标，已保存的其他目标可切换；详细计算和多条成绩说明折叠。及格结果始终单独呈现，真实失败不会被折叠。
- `validateCourse` 增加 `errorGroups`，最终确认始终校验整门课；有错时跳回对应步骤并展开选填项。修改规则仍撤销确认，存储格式/键未改。

文件：`dist/app.mjs`、`dist/rules-view.mjs`、`dist/student-ui.css`、`dist/index.html`、`dist/calc.mjs`；开发接口文档与验收说明同步更新。
