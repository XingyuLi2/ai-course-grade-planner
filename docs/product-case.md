## 1. 项目概述

AI 课程成绩规划工具面向需要根据课程规则安排目标分数的学生。核心流程为 **材料导入 → 生成成绩表 → 核对与修正 → 预计试算 → 持续更新**。

当前交付单课程交互 Demo：配套截图和文字采用明确标注的“模拟提取”，计算、成绩修改确认和浏览器本地保存真实实现。产品代码已发布到 GitHub，公网 Demo 尚未部署。

## 2. 问题与目标用户

项目来自发起人的课程算分经历：每次新成绩公布，都要重新整理考核权重、已有分数、目标和额外及格要求，再交给 AI 计算。一次问答可以得到结果，却没有形成便于持续更新的成绩记录。

目标用户是课程有多项加权考核、希望了解后续分数要求的学生，重点覆盖三个时点：

| 使用时点 | 用户要完成的任务 | 产品要解决的问题 |
| --- | --- | --- |
| 拿到课程评分说明 | 整理项目、权重、满分与及格要求 | 从材料生成可核对的成绩表，避免从空表逐项录入 |
| 考核尚未出分 | 试算某项预计分数下的剩余要求 | 区分当前实际成绩与假设结果 |
| 新成绩公布或被调整 | 更新记录，重新查看目标差距 | 保留其他成绩，保护已经确认的数据 |

当前需求依据为个人场景与原型反馈，外部同学观察尚未开展。

## 3. 需求拆解与优先级

| 优先级 | 需求 | 本轮交付 |
| --- | --- | --- |
| P0 | 材料生成成绩表 | 配套截图／文字样例可生成成绩表，展示“演示样例 / 模拟提取” |
| P0 | 生成后核对与修正 | 成绩表直接可见，可改名称与规则，核对后开始计算 |
| P0 | 两种目标计算 | 根据实际成绩查看剩余整体要求；填写预计成绩后继续倒推 |
| P0 | 持续更新与改分保护 | 已出成绩默认锁定，修改／清除需核对确认，取消保留原值 |
| P0 | 同浏览器保存 | 保存课程、实际与预计成绩、目标；提示保存异常和记录冲突 |
| 后续 | 真实模型提取 | 已准备 Prompt 和实验材料，网页尚未接入 API |
| 后续 | 多课程、账号与同步 | 本轮保持单课程范围 |

自己的新材料当前只在本机预览并提示未识别；不会生成配套样例的固定答案。

## 4. 核心流程与状态

1. **导入材料：**选择演示截图或文字，查看对应材料并生成成绩表。
2. **核对结果：**检查考核项目、占比、满分和及格要求；有问题时就地修正。
3. **查看实际要求：**只依据已出成绩计算当前贡献、目标差距和剩余整体要求。
4. **填写预计分数：**查看当前假设下的要求。实际已获分数保持不变。
5. **更新已出成绩：**输入新分数，核对原值与新值，再确认保存；同项预计清空，其他成绩保留。
6. **继续使用：**在同一浏览器与地址重新打开，恢复已有课程记录。

规则待核对、信息缺失、来源冲突与暂不支持的规则分别提示。只有规则完整且受支持时才给出正式计算结果。详细状态见 [状态设计](state-design.md)。

## 5. 关键产品决策

| 决策 | 原因 | 对应设计 |
| --- | --- | --- |
| 先生成，再修正 | 用户首先需要省去整理和抄写课程信息 | 修正入口放在成绩表之后，取消手工建课前置步骤 |
| 已出成绩可修改，但需要确认 | 老师可能调整成绩，同时应避免随手误改 | 编辑草稿与已保存值分开，确认前显示变化，取消恢复 |
| 实际与预计分开 | 假设分数和真实记录回答不同问题 | 两种计算视角分开；同项有实际成绩时以实际值为准 |
| 总评与额外及格要求分开判断 | 总分足够时，期末仍可能需要达到最低分 | 单项最低分独立展示，未知不当作零分 |
| 提取与计算分工 | 材料理解需要核对，数值判断需要可复现 | 提取产生候选规则，确认后交给确定性逻辑计算 |
| 先支持本地单课程 | 优先跑通首次导入与第二次更新 | 暂缓多课程和同步；换浏览器或地址不共享记录 |

## 6. 从前置表单到生成后修正

初版要求用户手工填写课程规则。发起人使用后提出页面长、术语难懂的问题，第一轮将内容分为三个分类，改用学生熟悉的表达，并给必要术语补充就近解释。

进一步复核发现，拆分表单仍然要求用户手工整理整门课。主流程随后调整为材料生成成绩表，原有规则编辑能力保留为生成后的修正入口。与此同时，已出成绩由直接输入改为锁定展示，通过编辑、核对和确认完成修改。

这次迭代调整了任务顺序和数据保护方式。当前已落地代码与自动检查，交互理解和任务完成效果将在后续同学观察中评估。

## 7. 演示算例

合成课程中，A 占 30%、满分 20、实际得分 16；B 占 20%、满分 40；期末占 50%、满分 100，最低要求为 50 分。目标总评为 75 分。

| 操作 | 实际已获总评分 | 展示结果 |
| --- | --- | --- |
| 只有 A 实际 16/20 | 24 | 总评还差 51 分，剩余最多贡献 70 分，整体约需 73%（向上取整显示） |
| B 填预计 30/40 | 仍为 24 | 按当前预计，期末需 72/100 |
| B 确认录入实际 32/40 | 40 | B 的预计清空，期末需 70/100；A 的实际成绩保留 |

这组例子体现了两种视角的区别：预计分数改变试算条件，实际出分才改变已获得的总评分。计算口径与人工算例见 [计算规范](calculation-spec.md)。
