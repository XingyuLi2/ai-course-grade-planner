# 产品案例：让课程算分从一次问答变成持续记录

更新：2026-11-25。项目：**AI 课程成绩规划工具｜单课程交互 Demo**。当前以配套合成材料演示导入，提取结果为预置数据；计算、成绩修改确认和浏览器本地保存真实实现。真实模型实验与同学观察尚未完成。

## 问题从哪里来

项目发起人在课程出分后，需要再次整理考核权重、历史成绩、个人目标与额外及格要求，再交给 AI 计算剩余分数。由此提出一个待验证的产品假设：把课程规则和已出成绩留下，每次只更新新成绩，可能减少重复整理。

需求依据目前是发起人的个人经历和对原型的反馈，没有外部用户访谈、操作耗时对照或需求规模数据。因此，本案例展示已做出的产品判断和可检查的实现，不把假设写成已经证明的效率提升。

## 核心任务与交付范围

核心任务是：**材料导入 → 生成成绩表 → 核对与按需修正 → 预计试算 → 出分后持续更新**。

- 新课程从配套截图或文字开始，直接生成成绩表，取消逐项手工建课的前置流程。自己的新材料当前仅预览，并明确说明尚未识别。
- 已出成绩与预计成绩分开。预计分数可随时调整；已出成绩默认锁定，进入修改、核对原值与新值、确认后才生效。
- 同一浏览器保存一门课程。再次打开可以继续更新，当前没有账号、云同步、多课程或数据备份功能。

本轮先完成可演示的交互和可核查的计算。未接入真实模型，配套材料与预置结果始终标为“演示样例 / 模拟提取”；没有把自有材料套进固定答案。

## 关键产品取舍

| 选择 | 为什么这样做 | 当前边界与代价 |
| --- | --- | --- |
| 生成后修正，去掉手工建课前置 | 用户希望省去整理过程；即便把长表单拆成几步，仍要求从空表抄写整门课 | 配套样例只能展示目标体验，不能证明真实识别可用 |
| 已出成绩锁定，但允许确认后修改 | 成绩可能被调整，完全禁止修改不合适；直接可编辑又容易误改 | 多一次核对动作；是否易懂仍需同学实际操作验证 |
| 实际与预计分开保存、分开解释 | 预计是用户假设，不能让“假设拿到的分数”看起来已经到手 | 页面需要同时表达当前事实和条件性结果 |
| 核对规则后再给正式结果 | 满分、权重或单项最低分一旦错误，后续算式即使正确也会误导 | 不完整、冲突或不支持的规则会阻止正式判断，不能一键跳过 |
| 规则提取与确定性计算分工 | 模型适合整理材料；加权、倒推与最低分判断需要可复现的规则 | 提取 Prompt 已准备，但当前网页没有模型调用或候选结果自动导入接口 |
| 先做单课程本地保存 | 聚焦首次导入和第二次更新，不把登录、同步变成演示前提 | 换浏览器、域名或端口不共享记录，清理站点数据会丢失记录 |

## 一次实际的方向修正

初版要求用户手工填写课程规则。发起人反馈页面太长、专业词难理解后，先将输入拆成三个分类并调整学生用语；随后进一步指出，前置填课本身偏离了省去整理的核心目标。

最新实现因此改为由材料生成成绩表，把原有规则编辑能力移到生成之后；同时加入已出成绩的确认修改。这里的变化是任务顺序发生调整，不只是页面变短。已有代码与应用事件检查支持这些实现已落地，但尚不能证明新方案比旧方案更省时或更易用。

反馈来自项目发起人，不称为同学访谈。公开摘要只保留问题、选择与实现，不包含私人课程记录或原始聊天。

## 用一个合成例子说明结果

样例设作业 A 占 30%、满分 20、实际得分 16；作业 B 占 20%、满分 40；期末占 50%、满分 100，并要求期末至少 50 分。目标设为总评 75 分。这些均为合成规则，不是某学校的成绩标准。

| 时点 | 已获得的总评分 | 结果及含义 |
| --- | --- | --- |
| 只有 A 实际 16/20 | `30 × 16/20 = 24` | 总评还差 51 分；其余最多贡献 70 分，整体约需 73%（向上取整显示），不能据此确定唯一的期末分数 |
| 给 B 填预计 30/40 | 仍为 24 | 按这个假设，B 贡献 15 分，期末需 `(75−24−15) ÷ 0.5 = 72` 分 |
| B 实际出分，确认录入 32/40 | `24 + 20 × 32/40 = 40` | 同项预计失效并清空，期末需 `(75−40) ÷ 0.5 = 70` 分；A 的实际成绩保持不变 |

预计值不能增加实际已获分数；总评够了，也不一定满足单项最低分要求。未知分数与实际零分必须分开。这些约束既写入计算，也进入测试。

## 角色与协作方式

发起人负责提供问题场景、确定核心任务、提出交互反馈与明确演示边界，包括去掉前置手工建课、生成后可修正、保护已出成绩及本轮无需 API。

Codex 辅助拆解方案、编写代码、形成计算契约与 Prompt、执行自动检查并整理文档。技术方案与测试脚本不表述为发起人独立手写；发起人的产品贡献以实际提出和确认的决策为依据。文档中提出的验证方案不等于发起人已独立执行或掌握全部技术细节。

## 下一步需要哪种证据

1. 完成真实浏览器核心路径与异常路径检查，补齐弹窗取消、刷新恢复、规则修正、窄窗口和键盘操作的记录。
2. 取得可用课程材料后，用固定 Prompt 做独立模型实验，保留首次回复与逐字段比对；该实验无需先把 API 接到网页。
3. 观察同学首次核对、第二次更新与预计试算的过程，记录任务完成、误解、求助和真实耗时，再决定是否修改。模拟提取的等待时间不能用于宣称识别更快。

本轮可交付的是有清楚能力边界的产品 Demo、设计理由和验证证据；需求普遍性、模型质量与用户效果仍需各自的实际材料。
