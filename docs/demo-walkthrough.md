# 演示脚本

用途：演示或录屏时说明“为什么这样设计”，并让观看者看到分数如何变化。录屏尚未完成，下列是讲解脚本，不是新增验收记录。

当前使用合成课程，提取明确标为模拟；计算与本地保存真实实现。此前只对本地已有课程完成部分走查，范围见 [实际记录](verification-browser-2026-11-25.md)。

## 1. 三个关键场景

| 场景 | 演示动作 | 展示重点 |
| --- | --- | --- |
| 从材料开始 | 查看配套截图，生成成绩表并核对规则 | 生成后修正，无前置手工建课 |
| 预计试算 | 目标总评75，B预计30 | 实际已获24保持不变，期末需72 |
| 出分后更新 | B实际32，核对并确认；拟改31后取消、刷新 | 实际40、期末70，原32和A16继续保留 |

## 3. 约90秒讲解顺序

1. **场景：**“作业陆续出分，我想知道离目标还差多少，并在下次出分后继续更新。”
2. **从材料开始：**展示配套材料与模拟标识，生成成绩表后核对规则。“先得到一张表，有错再修正，不必从空表录入整门课。”若已有记录，先确认是否替换，只使用可丢弃的合成演示记录。
3. **试算：**选择目标75，B预计填30。“期末需72是依赖这个假设的结果，实际已获仍然是24。”
4. **更新：**B实际录入32，展示核对与最终确认。“确认后实际已获变40，期末需70；B的旧预计清空，A仍保留。”
5. **保护记录：**拟改31后取消并刷新。“未确认的修改不生效，实际成绩仍为32。”
6. **证据边界：**“计算和更新逻辑已有自动检查，本地部分操作已走查；真实模型提取、同学观察和完整浏览器验收还需补证据。”

每次录屏都实际执行操作并核对结果，记录浏览器、访问地址、日期、视口和覆盖范围。没有实际完成的步骤保留为待验收，不能用剪辑或主图代替。
