# 独立模型实验准备

日期：2026-11-25。**M4 尚未执行；当前没有模型原始回复、准确率、等待时间或成本结果。**

这里提供 [固定 Prompt v0.1](../prompts/extract-rules.md)、[5 个合成输入与标准答案](cases.jsonl) 和 [逐例记录模板](run-template.md)。全部例子都是“演示样例”，不对应任何学校的真实规则。标准答案是依据输入逐项标注的预期，不是模型运行结果。

## 现在可以检查什么

| 案例 | 核对重点 | 人工预期 |
| --- | --- | --- |
| SYN-001 | 完整材料、不同满分、实际与预计分开 | 字段齐全，仍是待确认候选；期末 hurdle 为单项得分率 >= 50% |
| SYN-002 | 未提供满分、未提到门槛 | 缺失满分保持 null；门槛状态 unknown，不能擅自补 100 分或无门槛 |
| SYN-003 | 两份材料的门槛冲突 | 40% 与 50% 均保留，选定阈值 null，请学生核对 |
| SYN-004 | 严格大于 | 保留 > 50%，标记暂不支持，不改成 >= |
| SYN-005 | 去掉最低成绩 | 保留去掉最低一次的原文，标记暂不支持，不当普通加权课程算 |

五例的 `source_type` 都是 `synthetic`。它们只能用于开发期的边界检查，不能支持真实课程泛化结论。真实材料至少还需补一份；同一课程截图的文字重写应共用 `source_group`，不能算成新的独立课程。

`cases.jsonl` 每行是一个 JSON 对象：`input.materials` 是应提交给模型的输入，`gold` 是人工标准答案，`required_findings` 是必须发现的语义问题。提交时**只复制 input**，不让模型看到答案。`gold` 的字段名与 Prompt 对齐，项目 ID 可在比对时按名称对应；问题措辞不必逐字一致。数值可接受等价十进制表达，但严格区分 null 与零、> 与 >=、原始分与百分比。

## 取得材料后的操作

1. 选择用户已有、支持待测输入类型的模型对话工具，记录界面可见模型名称。隐藏版本记为未知。无需先接网页 API。
2. 将真实材料、真实成绩与原始回复留在本仓库之外的私人目录；公开目录只保留已脱敏且允许公开的内容。手动提交给云端对话工具会联网处理材料，“网页之外实验”不代表离线运行。
3. 每例新建会话，复制固定 Prompt 并附该例材料。记录 Prompt 版本、输入类型、材料编号与日期。复用会话时保留所有相关上下文。
4. 保存首次原始回复，再使用模板逐字段核对。需要追加提示或纠正时，分别保留首次输出与修订输出，不能将最后正确结果冒充首次正确。
5. 核对 name、totalMax、各 item 的权重/满分/实际/预计/步长、通过线、各目标、hurdle 对象/符号/阈值/单位/关系，以及缺失、冲突、未支持规则和来源引用。JSON 能解析只算格式检查。
6. 确认有实际输出后才能填写结果。若汇总，给出正确字段数/标注字段数、整例正确数/案例数、hurdle 错误例数、无依据新增字段；人工纠正后的结果单列。真实、衍生和合成案例分开汇总。

是否测量时间/成本取决于工具实际可见信息。手工复制时间、模型回复等待时间和 API 响应时间不能混写；没有计量就填“未取得”，不要估造。

## 当前实现与实验的关系

本地 Demo 采用原生 HTML/CSS/JavaScript 与浏览器本地保存，由 Python 提供本机页面服务。没有第三方网页框架依赖，目的在于先验证确认规则、更新成绩与试算；具体运行和验证状态以 [产品 README](../README.md) 与 [验证说明](../docs/validation.md) 为准。

真实计算、页面保存、合成样例的“模拟提取”、M4 独立实验、E1 网页 API 接入分别报告。准备这份 Prompt 及案例不算 M4 完成；之后即使 M4 有结果，也不能移除网页上的模拟标记或宣称网页接入了模型。
